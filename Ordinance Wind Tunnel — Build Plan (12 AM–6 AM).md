# Ordinance Wind Tunnel — Build Plan (12 AM–6 AM)

Oct 9, 2026 · @Angel Dominic Lopez

## What we're building

Ordinance Wind Tunnel lets a barangay or city councilor paste a draft ordinance and see how up to 200 simulated residents react before it is filed, with every model call running offline on an RTX 3060.

- **Crowd (50–200 residents):** generated by code from traits (age, job, income, commute, purok). Each returns a short JSON reaction: stance, impact 1–5, comply/partial/evade, one Taglish quote. Shown as a live grid of colored dots with filters.
- **Deep panel (6–8 residents):** hand-written personas (tricycle driver, vendor, student, senior, tanod, sari-sari owner, loophole hunter) with a full answer: reaction, life impact, loophole.
- **Report:** one final call that turns the crowd stats and panel answers into who is hurt most, top loopholes, and suggested clause amendments.
- **Loop:** edit the ordinance, re-run, compare the before and after stance split.

The UI must label results as simulated reactions, not a survey.

## Tech stack

Use Ollama with one 3B model on the RTX 3060 Laptop (6 GB VRAM) and a Vite + React page that calls it through a dev proxy; there is no backend to write.

| Layer | Choice | Why |
| --- | --- | --- |
| Your machine | ASUS TUF F17, i7-12700H, 16 GB RAM, RTX 3060 Laptop 6 GB VRAM | Sets every choice below |
| Local inference | Ollama for Windows | One install, uses the NVIDIA GPU via CUDA, HTTP API on `localhost:11434`, JSON-schema output |
| Model (crowd, panel, report) | `qwen2.5:3b` (about 2 GB) | Fits fully in 6 GB VRAM with room for 2 parallel requests; roughly 60–90 tokens/sec |
| Backup model | `gemma3:4b` (about 3.3 GB) | Try only if Qwen's Taglish is poor; parallel drops to 1–2 |
| Not used | `qwen2.5:7b` | About 4.7 GB; with context memory it spills into system RAM and slows 3–5x |
| Context size | `num_ctx: 2048` per request | Halves memory per request vs the default, which is what lets 2 run at once |
| Frontend | Vite + React (JavaScript) | Fast setup, live reload |
| Styling | Plain CSS with CSS variables | Dot grid is a CSS grid |
| Charts (optional) | Recharts | Stance-by-occupation bars |
| Runtime | Node.js 20+ LTS | Needed for Vite |
| Repo | Git + public GitHub repo | Required by the rules |

**Expected speed on your laptop:** about 1–2 seconds per crowd resident, 2 at a time, so 50 residents ≈ 40–60 s, 100 ≈ 1.5–2 min, 200 ≈ 3–4 min. Plan the live demo at 50, show a saved 200 run.

**Laptop rules:** keep it plugged in (the GPU throttles on battery), set Windows power mode to Best performance, and close Chrome tabs and games while running, since 16 GB RAM is shared with the browser.

**2. Ollama settings (PowerShell, then quit Ollama from the tray and reopen it)**

```
setx OLLAMA_NUM_PARALLEL 2
setx OLLAMA_KEEP_ALIVE -1
setx OLLAMA_MAX_LOADED_MODELS 1

```

`ollama ps` must show **100% GPU** for the model. If it shows a CPU/GPU split, lower `num_ctx` or `OLLAMA_NUM_PARALLEL` to 1. Update the NVIDIA driver (yours is from September 2025) only if Ollama fails to detect the GPU.

```

**4. Proxy Ollama through Vite (avoids browser CORS errors).** In `vite.config.js`:

  server: { proxy: { '/ollama': { target: 'http://localhost:11434', rewrite: p => p.replace(/^\/ollama/, '') } } }
})
```

The app then calls `/ollama/api/chat`. Run it with `npm run dev`.

## Core logic

The crowd is fast because each resident answers in about 40 tokens of forced JSON, and four run at once.

**Persona generator (`personas.js`)** builds residents from weighted trait tables with a fixed seed, so the same 200 come back every run and before/after comparisons are fair.

- Occupation (weighted): tricycle driver, jeepney driver, market vendor, sari-sari owner, construction worker, BPO agent, student, teacher, OFW family, senior/retired, fisherfolk, government employee, small business owner
- Age band, income bracket (below ₱10k, ₱10–25k, ₱25–50k, above ₱50k per month), commute mode, household size, purok 1–7
- Output: `{ id, name, age, job, income, commute, household, purok }`

**Crowd schema (`schemas.js`)**

```
{ "type": "object",
  "properties": {
    "stance": { "enum": ["support", "mixed", "oppose"] },
    "impact": { "type": "integer", "minimum": 1, "maximum": 5 },
    "comply": { "enum": ["comply", "partial", "evade"] },
    "quote":  { "type": "string" }
  },
  "required": ["stance", "impact", "comply", "quote"] }
```

Panel schema adds `reaction`, `life_impact`, `loophole`. Report schema: `most_affected[]`, `top_loopholes[]`, `amendments[{clause, change, reason}]`.

**Crowd prompt (`prompts.js`)**

```
System: You simulate one resident of a Philippine barangay reacting to a draft ordinance.
Stay in character. Answer only in the JSON schema. Quote is one Taglish sentence, max 20 words.
User: Resident: {age}-year-old {job}, earns {income}/month, commutes by {commute}, household of {household}, Purok {purok}.
Ordinance: {text}
```

**Ollama call (`ollama.js`)**

```
export async function chat({ model, system, user, schema, numPredict = 80, signal }) {
  const res = await fetch('/ollama/api/chat', {
    method: 'POST', signal,
    body: JSON.stringify({
      model, stream: false, format: schema,
      options: { temperature: 0.8, num_predict: numPredict, num_ctx: 2048 },
      messages: [{ role: 'system', content: system }, { role: 'user', content: user }]
    })
  })
  const data = await res.json()
  return JSON.parse(data.message.content)
}
```

Panel cards use `stream: true` and read the response line by line so text appears as it generates.

**Pool (`pool.js`)** runs tasks with a limit equal to `OLLAMA_NUM_PARALLEL`, calls `onResult(i, result)` as each finishes so dots light up live, retries a failed parse once, and marks the dot gray if it fails twice.

**Report** receives counts by stance, occupation, and comply, plus the panel answers and 10 sampled quotes, never all 200 raw answers, so the prompt stays small.

**Why does this product benefit from running AI locally?** (draft answer)

Draft ordinances are confidential until filed, so councilors cannot paste them into a cloud chatbot. Simulating 200 residents is hundreds of model calls per draft, and each edit reruns them, which costs nothing locally but adds up on a paid API. Many barangay and municipal offices have unreliable internet, and this works with the cable unplugged.

## Risks and fallbacks

The biggest risk is spending past 3:00 AM on prompt tuning; if quotes are "good enough" by then, move on to the UI.

| Risk | Sign | Fallback |
| --- | --- | --- |
| 200 run too slow | 50 residents take over 2 min | Live demo with 50; show saved 200 run, labeled |
| All residents say "oppose" | Stance split above 90% one way | Add "your honest view, which may be supportive" to the prompt; raise temperature to 0.9 |
| Bad or English-only Taglish | Quotes read like a textbook | Add 3 example Taglish quotes in the system prompt |
| JSON parse fails | Gray dots | Already handled: retry once, then skip |
| Model spills out of 6 GB VRAM | Ollama errors or very slow | `Set OLLAMA_NUM_PARALLEL to 1 and num_ctx to 1536; check ollama ps shows 100% GPU` |
| CORS error in browser | Fetch blocked | Check the Vite proxy path is `/ollama` |
| Ollama not running at demo | Connection refused | Start Ollama and warm the model before recording |
| Repo still private | Judges can't see it | Make it public by 8:30 AM at the latest |
