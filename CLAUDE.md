# LawGetherness: offline ordinance simulator (hackathon project)

Hackathon: AppBuildersPH. **Deadline: 10:00 AM, October 10, 2026. No extensions. Submit once.**
Every submission must answer: **Why does this product benefit from running AI locally?**

Tagline: *Test a draft ordinance on 200 simulated residents before it becomes law, fully offline.*

---

## 1. What it does

A councilor or barangay official pastes a draft ordinance. The app simulates how residents react:

- **Crowd (50, 100, or 200 residents):** generated by code from traits (age, job, income, commute, household, purok). Each resident returns a short JSON reaction: stance, impact 1-5, comply/partial/evade, one Taglish quote. Shown as a live grid of colored dots with filters.
- **Deep panel (6-8 residents):** hand-written personas (tricycle driver, market vendor, student, senior citizen, tanod, sari-sari store owner, loophole hunter). Each gives a full answer: reaction, life impact, loophole.
- **Report:** one final call that turns crowd stats and panel answers into who is hurt most, top loopholes, and suggested clause amendments.
- **Loop:** edit the ordinance, re-run, compare the before/after stance split.

The UI must clearly say: **"Simulated reactions from a small local model, not a real survey."**

## 2. Hard rules for the code (follow always)

- All AI inference is local via Ollama at `http://localhost:11434`. **No cloud AI APIs.**
- Machine: ASUS TUF F17, i7-12700H, 16 GB RAM, **RTX 3060 Laptop with 6 GB VRAM**.
- Model: `gemma3:4b` (switched from `qwen2.5:3b`, whose Taglish was garbled; benchmark: gemma 50 residents in ~74 s, 100% GPU, ~3.9 GB VRAM at concurrency 2). Model name lives in `MODEL` in `src/lib/ollama.js`. Do not settle for a mediocre model: if a better one fits 6 GB VRAM, benchmark it and switch. Do NOT use 7B+ models; they spill out of 6 GB VRAM.
- Ollama env vars: `OLLAMA_NUM_PARALLEL=2`, `OLLAMA_KEEP_ALIVE=-1`, `OLLAMA_MAX_LOADED_MODELS=1`, `OLLAMA_FLASH_ATTENTION=1`.
- Every request sets `num_ctx: 2048`. Crowd calls set `num_predict: 80`.
- Pool concurrency = 2. If the model spills out of VRAM, drop to concurrency 1 and `num_ctx` 1536.
- Use Ollama structured output (the `format` field with a JSON schema) for every call.
- JavaScript + React (Vite), not TypeScript. Plain CSS. No backend.
- Browser calls `/ollama/api/chat`; `vite.config.js` proxies `/ollama` to `localhost:11434` (avoids CORS).
- Persona generation is plain seeded code, not AI. Same seed = same 200 residents every run.
- The report prompt receives aggregated stats plus about 10 sampled quotes, never all 200 raw answers.
- Retry a failed JSON parse once; if it fails twice, mark that resident gray and continue.
- Show an offline badge using `navigator.onLine` for the demo.
- Never commit secrets. Do not add features that are not in this plan.

### Working style for Claude Code
- Build one step at a time and stop after each so I can test.
- Keep code simple and commented; time is limited.
- Commit after each working step (hourly commits prove the work was built during the hackathon).

## 6. Core logic

**Persona generator (`personas.js`)** uses weighted trait tables and a fixed seed.
- Occupation (weighted): tricycle driver, jeepney driver, market vendor, sari-sari owner, construction worker, BPO agent, student, teacher, OFW family, senior/retired, fisherfolk, government employee, small business owner
- Age band, income bracket (below P10k, P10-25k, P25-50k, above P50k per month), commute mode, household size, purok 1-7
- Output: `{ id, name, age, job, income, commute, household, purok }`
- State in the README that the mix is approximate.

**Crowd schema (`schemas.js`)**

```json
{ "type": "object",
  "properties": {
    "stance": { "enum": ["support", "mixed", "oppose"] },
    "impact": { "type": "integer", "minimum": 1, "maximum": 5 },
    "comply": { "enum": ["comply", "partial", "evade"] },
    "quote":  { "type": "string" }
  },
  "required": ["stance", "impact", "comply", "quote"] }
```

Panel schema adds `reaction`, `life_impact`, `loophole`.
Report schema: `most_affected[]`, `top_loopholes[]`, `amendments[{clause, change, reason}]`.

**Crowd prompt (`prompts.js`)**

```
System: You simulate one resident of a Philippine barangay reacting to a draft ordinance.
Stay in character. Your honest view may be supportive, mixed, or opposed.
Answer only in the JSON schema. Quote is one Taglish sentence, max 20 words.
User: Resident: {age}-year-old {job}, earns {income}/month, commutes by {commute}, household of {household}, Purok {purok}.
Ordinance: {text}
```

**Ollama call (`ollama.js`)**

```js
export async function chat({ model = 'qwen2.5:3b', system, user, schema, numPredict = 80, signal }) {
  const res = await fetch('/ollama/api/chat', {
    method: 'POST', signal,
    body: JSON.stringify({
      model, stream: false, format: schema,
      options: { temperature: 0.8, num_predict: numPredict, num_ctx: 2048 },
      messages: [{ role: 'system', content: system }, { role: 'user', content: user }]
    })
  })
  const data = await res.json()
  return JSON.parse(data.message.content)
}
```

Panel cards use `stream: true` and read the response line by line so text appears as it generates.

**Pool (`pool.js`)** runs tasks with a concurrency limit of 2, calls `onResult(i, result)` as each finishes so dots light up live, retries a failed parse once, and marks the dot gray on a second failure.

**Report** receives counts by stance, occupation, and comply, plus the panel answers and about 10 sampled quotes.

**Why does this product benefit from running AI locally?** (draft answer for the README)

Draft ordinances are confidential until filed, so councilors cannot paste them into a cloud chatbot. Simulating 200 residents takes hundreds of model calls per draft, and every edit reruns them. That costs nothing locally but adds up on a paid API. Many barangay and municipal offices have unreliable internet, and LawGetherness works with the cable unplugged.
