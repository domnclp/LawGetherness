# LawGetherness

**Test a draft ordinance on 200 simulated residents before it becomes law, fully offline.**

A councilor or legislative staffer pastes (or attaches) a draft ordinance. LawGetherness simulates how a barangay's residents would react, explains why, and turns that into amendments the council can act on. Every model call runs on the laptop's own GPU through Ollama, so a confidential draft never leaves the room.

> **Simulated reactions from a small local model, not a real survey.** Use it to prepare a public consultation, not to replace one.

Built for the AppBuildersPH hackathon (October 10, 2026) by **Choco Mallows**: Zyrene Tapayan (UI) and Angel Dominic Lopez (engine).

---

## What it does

1. **Brief (1 model call).** The draft is turned into plain-language facts every resident reasons from: what changes, what is still allowed, who must change, penalties, exemptions, a legal and ethical check (does it punish people for who they are? is the penalty excessive? likely unconstitutional?), concrete everyday scenes, and the open questions a council must weigh.
2. **Crowd (50, 100 or 200 residents, 1 call each).** Residents are generated by seeded code (same seed = same people) from approximate Philippine traits: age, job, income, commute, household, who they live with, work hours, values. Each resident:
   - decides whether the rule touches their actual life (`touches_me`, `impact` 1-5);
   - **weighs both sides before judging**: who the rule helps and how, and who it hurts and how;
   - gives a judgment (good rule / good but costly / unfair or harmful / pointless), a stance (support / mixed / oppose), whether they would comply, partly comply or evade, one Taglish quote, and (if affected) one concrete point for the lawmaker.
   The map fills in live as answers arrive.
3. **Consistency checks (code, no extra model).** Each answer is checked against the resident's real profile and the ordinance: wrong hours, misreading the rule, invented relatives or habits, off-topic job talk, a stance that contradicts its own reasoning, duplicate quotes. A failing answer is re-asked once with the specific problem named; label clashes are reconciled in code.
4. **Togetherness summary.** What the community actually thinks, in a few sentences, with the mood computed from the real split.
5. **Deep panel (8 hand-written personas, streamed).** Tricycle driver, market vendor, senior-high student, senior citizen, barangay tanod, sari-sari store owner, a trans salon owner, and a loophole hunter, each with a full answer: life impact, reaction, loophole, what would help.
6. **Report.** Headline, who is hurt most, top loopholes, and up to 3 clause-level amendments (checked against the draft's sections and re-asked once if one cites a section that does not exist). One click adds an amendment to the draft. Re-run and compare the before/after split.
7. **Council memo export.** A print-ready one-page brief: headline, the split and compliance, how residents weighed it (the gains and losses they named, clustered with counts), who is hurt with per-group numbers, loopholes, amendments, and the "simulated, not a survey" notice. Print it or save it as PDF for a committee hearing.

Also: attach `.txt`, `.md`, `.docx` or `.pdf` drafts (parsed in the browser, no upload); real Quezon City measures as presets, with saved 200-resident runs that open instantly and are labeled **Saved run** (at 50 or 100 residents the saved crowd replays instantly and the panel and report run live); an offline badge driven by `navigator.onLine` that also shows whether the local model is running.

## Why does this product benefit from running AI locally?

- **Confidentiality.** Draft ordinances are confidential until filed. Councilors cannot paste them into a cloud chatbot; here nothing leaves the laptop, and the app works with Wi-Fi off.
- **Hundreds of calls per draft.** One 200-resident run is about 230 model calls, and every edit re-runs them. Locally that costs nothing; on a paid API it adds up with every revision.
- **Unreliable internet.** Many barangay and municipal offices have poor connectivity. LawGetherness needs none at run time.

## What runs locally, and what needs the internet

- **Local (all of it at run time):** every model call (brief, 200-resident crowd, summary, panel, report) through Ollama on the RTX 3060 Laptop GPU; persona generation; document parsing; the council memo; saved runs. All data stays on the laptop.
- **Internet:** only the one-time download of Ollama, the model and the npm packages. Nothing at run time.

## Benchmarks

Measured on the demo laptop (ASUS TUF F17, i7-12700H, RTX 3060 Laptop 6 GB), `gemma3:4b`, 2 requests in parallel. Details and the accuracy method: [BENCHMARK.md](BENCHMARK.md).

| Crowd size | Live run (crowd only) | Saved preset |
| --- | --- | --- |
| 50 residents | about 1.5-2 minutes | instant crowd; panel and report about 1 minute |
| 200 residents | about 6-8 minutes (1.7-2.3 s per resident) | instant, everything |

Engine v3 made the crowd 35-45% faster than v2 while adding the who-gains / who-loses weighing (24-resident benchmark: 94-101 s down to 50-64 s, 0 failed residents).

## Run it

Requirements: Windows with an NVIDIA GPU (6 GB VRAM is enough), [Ollama](https://ollama.com), Node.js 20+.

```powershell
setx OLLAMA_NUM_PARALLEL 2
setx OLLAMA_KEEP_ALIVE -1
setx OLLAMA_MAX_LOADED_MODELS 1
setx OLLAMA_FLASH_ATTENTION 1
# quit Ollama from the system tray and reopen it, then:
ollama pull gemma3:4b
npm install
npm run dev
```

Open the local URL Vite prints. The browser talks to Ollama through the Vite proxy (`/ollama` -> `http://localhost:11434`), so there is no backend and no CORS setup.

## Disclosures

- **Models:** `gemma3:4b` (Gemma 3 by Google, via Ollama). `qwen2.5:3b` was tested first and rejected (garbled Taglish).
- **Technologies and frameworks:** Ollama, Vite, React, Node.js, plain CSS. `recharts` is installed but not used in the current UI.
- **APIs and cloud services:** none at run time. The only API is Ollama's local HTTP API on `localhost`.
- **Existing code and assets:** Vite React template. The 4 preset ordinances are plain-language summaries of real Quezon City measures based on public sources (official titles, city notices, Supreme Court text); they are not the full legal texts, and penalty details the sources don't state are left out rather than invented. Photo credits: [public/images/CREDITS.md](public/images/CREDITS.md).
- **AI development tools:** Claude Code (Anthropic) in VS Code for the engine; OpenAI Codex for the UI. Simulated residents and reports are generated at run time by the local model above.
- **Limitations:** the population mix is approximate, not census-weighted. A 4B model can still misread a rule or repeat itself; the consistency checks reduce this but do not remove it. Treat results as a rehearsal for consultation, not as public opinion.
