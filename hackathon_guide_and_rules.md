# Hackathon Guidelines, Rules & Submission Info

---

## 1. The Challenge

### What we're asking for
Create a working product that uses AI running locally on a user's device to solve a real problem.

Show why running AI locally creates an experience that would be difficult, expensive, slow, private, or impossible with a cloud-only approach.

### Any Kind of Product
* Productivity
* Developer tools
* Accessibility
* Education
* Finance
* Gaming
* Disaster Response
* Creative tools
* Enterprise tools
* Computer vision
* Personal assistants
* Privacy tools

---

## 2. Technical Requirements & Rules

### Required
* **Substantially built during the hackathon**
* **A meaningful part of AI inference executes locally**
* **A working product, demonstrated**
* **Models, APIs, frameworks, and major tools disclosed**
* **Core Local AI functionality works without depending entirely on a cloud AI API**

### Allowed
* Existing open-source models and libraries
* AI-assisted development
* Devin
* Cloud APIs as secondary components

---

## 3. FAQ: Rules and Tools

* **Can we use cloud APIs?**
  * Yes, as secondary components. Your core Local AI functionality must not depend entirely on a cloud AI API.
* **Can we use open-source models and libraries?**
  * Yes. Disclose every model, framework, and API in your submission.
* **Do we need a specific model, OS, or hardware?**
  * No. Any model, framework, operating system, or hardware platform works.
* **Can we use AI coding tools like Devin?**
  * Yes. AI-assisted development and Devin are allowed. Disclose the tools you used.
* **Can we reuse code we wrote before today?**
  * Your project must be substantially built during the hackathon. Disclose any existing code or assets.
* **Can people outside the hackathon help us?**
  * No. Participants proven to have received external help from people outside the hackathon are disqualified.

## 7. Judging Criteria

| Weight | Criterion | Focus / Key Questions |
| :--- | :--- | :--- |
| **25%** | **Problem & Usefulness** | Does it solve a genuine problem for a clear target user? |
| **25%** | **Local AI Implementation** | Is local inference fundamental, and does it give a meaningful advantage? |
| **20%** | **Technical Execution** | Does it actually work, reliably enough for a live demonstration? |
| **15%** | **Innovation** | Is it meaningfully different? Does Local AI enable something new? |
| **15%** | **Product & Demo Quality** | Is the UX usable, and is the live demonstration convincing? |

> **Note:** Half the score is usefulness and how real your Local AI is.
